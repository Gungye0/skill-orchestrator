# 실행 계획 출력 형식

계획은 아래 형식을 그대로 씁니다. `{ }` 부분만 바꿉니다.

```markdown
# 실행 계획

- 목표: "{사용자 목표 원문}"
- 수집한 스킬: {n}개 ({이름1}, {이름2}, ...)

| 단계 | 할 일 | 스킬 | 선택 이유 | 입력 | 출력 | 표시 |
|---|---|---|---|---|---|---|
| 1 | {할 일} | {스킬 이름} | {description의 어느 부분과 맞는지} | {형식: 출처} | {형식} | - |
| 2 | {형식 A → 형식 B} | (자동 변환) | 1단계 출력({형식 A})과 3단계 입력({형식 B})이 다름 | {형식 A} | {형식 B} | [자동 삽입] |
| 3 | {할 일} | 미매칭 | 맞는 스킬 없음 | {형식} | {형식} | - |
| 4 | {파일 삭제 / 메시지 전송} | {스킬 이름 또는 미매칭} | {이유} | {대상} | {결과} | ⚠ 실행 전 확인 |
| 5 | 결과 검증 | independent-judge | 원래 목표와 최종 결과물만으로 독립 평가 | 목표 원문 + {최종 결과물} | 평가 보고서 | [기본 검증] |

## 미매칭 단계

- {단계 번호}: {할 일}. 선택지: (a) 직접 수행 (b) 건너뜀 (c) 중단

## 알림

- {"검증 단계 생략: independent-judge 미설치" 등. 없으면 "없음"}

이 계획대로 진행할까요? (승인 / 수정 요청)
```

## 표시 규칙

| 표시 | 의미 |
|---|---|
| `[자동 삽입]` | 입출력 형식이 맞지 않아 자동으로 넣은 변환 단계 |
| `⚠ 실행 전 확인` | 외부 전송 또는 파일 삭제. 실행 직전에 다시 확인 |
| `[기본 검증]` | 기본으로 넣은 independent-judge 단계 |
| `미매칭` | 맞는 스킬 없음. 사용자에게 처리 방법을 물음 |
